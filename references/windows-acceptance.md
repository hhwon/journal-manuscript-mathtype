# Windows Word + MathType 7: mandatory final acceptance

Do this on a **copy** of the generated manuscript with MathType 7 and Microsoft Word installed and confirmed compatible. Linux structural checks alone do not establish that the object is editable.

## Test environment record

Record Windows version, Word version and architecture, installed MathType version, current build SHA, and system fonts. Keep the tested `.docx` unchanged as a golden fixture.

## Special check: formula fonts and preview versus editable MathType

Always record where the mismatch occurs: **(a) Word before double-click** (a fallback image), **(b) MathType editor after double-click** (MTEF font preferences), or **(c) Word after closing MathType** (possibly regenerated by MathType). These are distinct and must be diagnosed independently.

For the revised native test, expect Variable = *Times New Roman italic*, Number = Times New Roman regular, L.C. Greek = *Symbol italic*, operators = Symbol regular, full-size = 12 pt. Check **MathType > Style > Define** and **Size > Define** if the editor differs. Source controls may contain other user styles; do not blanket-change symbols, function names, Greek alphabets or font files. The Linux preview uses Tinos/ STIX approximations and cannot guarantee pixel-identical Times New Roman rendering until Windows recomputes the object preview.

## Acceptance steps

1. Open `.docx` in Microsoft Word. Dismiss any security warnings only if the document and source are trusted. Do not globally weaken Office macro/OLE protections.
2. Confirm titles, paragraphs, page numbers, all equations, captions, tables, figures and symbols display normally at 100% zoom. Specifically look for tiny fractions, displaced limits, missing Greek letters, clipped matrices and formula baselines.
3. Double-click a **simple inline equation**, change a character in MathType and return to Word. Confirm the in-line object updates and adjacent text stays correctly aligned.
4. Double-click a **display equation** involving a fraction and subscripts. Edit it, save, close, reopen, verify it is still editable and the `(n)` label remains right aligned.
5. Repeat for a **matrix / cases** formula, a **tensor with multi-level indices**, an **integral/sum with limits**, a **Greek/bold math** equation. Use `scripts/smoke_math.py` for the 12-formula corpus (requires installed backend).
6. Insert an additional numbered formula in the middle of the document, then select all text and press **F9** to update `SEQ` and `REF` fields. Check equation numbers and all cross-references. When Word asks whether to update fields in TOC, choose the relevant option. Some objects may need a manual field update.
7. Move a figure/table and update fields; confirm `Figure n`, `Table n` and references update together.
8. Save as DOCX, close Word, reopen and repeat checks 3 and 5. Optionally export to PDF and visually compare to Windows Word.
9. Re-run the Linux/package structural audit on the resulting DOCX after returning it to Linux.

## Pass/fail rules

**P0 blockers:** Word cannot open the file; OLE object does not activate MathType; an equation becomes a static image; an edited equation cannot be saved and reopened; Formula `Equation Native` data disappears; cross-reference fields become invalid.

**P1 blockers:** Any formula is clipped or materially different from LaTeX; formula baseline is clearly wrong; number overlaps equation; pictures and captions split inappropriately; table or figure labels break; text/spacing drift is large.

**P2 issues:** Small typography differences due to font availability, minor word wrapping differences, preferences for line/grid styling. Document each and revise intentionally.

A report should state **Linux structure: pass/fail**, **Word visual: pass/fail**, and **Windows MathType edit-save-reopen: pass/fail** separately. The last two are `unverified` until actually tested.

## Legacy objects and locally replaced donors

An `Equation.3` ProgID refers to legacy Equation Editor objects even though they may contain MTEF v3. Do not automatically declare successful MathType 7 activation. When validating a self-owned `ole_editor.py` replacement, inspect the *specific changed object* in Word as well as one unchanged old object. Check that the donor preview matches the editable MathType source, that the baseline is correct for inline equations, that numbering/cross-references remain valid, and that the native object survives save/reopen. Distinguish legacy v3 and modern v5 cases in the report.


## Native MTEF subset A/B/C test matrix

The native test DOCX contains A1-A7 newly encoded expressions, B1 a sigma-to-tau direct MTEF record patch, and C1 an untouched known-good MathType donor. In Windows Word with a locally installed compatible MathType, (1) open/inspect all formulas, (2) double-click A1, A3, A6, A7, B1 and C1 individually, (3) confirm MathType contents rather than PNG preview, (4) edit and save each, close Word and reopen, (5) report first failed ID with exact Word/MathType error. If C1 works but A1 fails, suspect newly generated MTEF; if C1 fails, suspect package/ProgID/Windows compatibility. Successful previews on Linux do not pass this test.

## v3 native font semantic tests

Use `MathType_Font_Semantics_Test_v3.docx` (15 OLE objects). Double-click and
compare these **inside MathType** to a manually typed formula using MathType's
Style > Define > Advanced dialogue:

- A2/A3: lower-case Greek and Latin indexed variables should use the original
  Symbol italic and Times New Roman italic settings.
- A5/A6: `sin`, `cos`, `exp`, and `ln` must be upright Function; ordinary
  variables and Greek arguments remain italic. Check function spacing.
- A7: `Re` must be upright Text, `u` must be bold upright Vector.
- A8: uppercase Greek Gamma and Sigma must be Symbol upright.
- A12: `det` must be upright Function, not three italic variables.
- B1: direct sigma-to-tau rewrite remains editable; C1 is the unchanged original.

Test Word preview **before activation**, native MathType view **after double
click**, Word view **after saving MathType**, then reopen DOCX and edit again.
If a mismatch remains, report the formula ID, whether it is Word preview or
MathType itself, and screenshots of the expression and Style > Define > Advanced
(in particular the Variable, Function and Greek entries). Linux confirms
binary style IDs, not pixel-perfect MathType Windows appearance.

## When equations do not display or cannot be edited: bisection test

Linux cannot run MathType, so find the faulty layer with one Word file of labelled variants, each changing one layer
(build it from a genuine MathType object of a document the user owns and from one generated object):

| item | container (compound file) | `Equation Native` header | MTEF | preview |
|---|---|---|---|---|
| T1 | genuine, verbatim | genuine | genuine | genuine WMF |
| T2 | genuine | genuine | genuine | generated PNG |
| T3 | generated | genuine | genuine | — |
| T3b | generated | generated | genuine | — |
| T4… | generated | generated | generated, simple (x = 1), matrix, integral | — |
| T5… | generated | generated | generated body + genuine preamble (fonts, prefs) | — |

Settings must not contain `w:updateFields` (Word would redraw everything on opening). Ask the user for one line per item
(`T1 ✓ T2 ✓ T3 ✗ …`) and the exact text of any error dialog. Reading: T1 ✗ → MathType/Word installation; T2 ✗ →
preview or document XML; T3 ✗ with T2 ✓ → the container; T3b ✗ → the 28-byte header; T4 ✗ with T5 ✓ → the MTEF
preamble; otherwise the MTEF body.

Symptoms seen so far and their causes (details in [mathtype-facts.md](mathtype-facts.md)):

| symptom in Windows | cause | fix |
|---|---|---|
| no equation is shown | root CLSID of the compound file missing | `ole_fix.set_root_clsid` |
| shown, but "update fields" blanks them; MathType cannot edit | malformed MTEF (stray END in empty slots, non-genuine template layouts) | `mtef_profile` layouts; `mtef_check.py` must parse every object |
| shown, MathType cannot open any of them | invalid compound-file directory tree (unsorted all-red chain) | `ole_fix.fix_dir_tree`; `cfb_treecheck.py` |
| integrals and tall brackets wrong after re-saving in MathType | Symbol style mapped to Times New Roman (no piece glyphs) | Symbol style = Symbol font, Symbol positions (`mtef_profile`) |
| size and look change after re-saving (fractions small, scripts large, gaps) | preview drawn with TeX rules, not MathType's | `preview_math` (MathType constants, spacing, integral, bar) |
| formula sits too high/low in the line | preview baseline unknown | `equation_layout` (`w:position` = −depth) |

To compare the preview with MathType's own rendering, ask the user to double-click one equation, close MathType
without changes (or re-save), and send a screenshot of the same equation before and after.
